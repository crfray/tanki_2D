# Tanki 2D — танки с рельсой

Браузерная 2D-игра про танковые дуэли, вид сверху. Механика снайперского
режима из Tanki Online: два лёгких корпуса, рельсотрон, два попадания до
смерти.

**Один HTML-файл, чистый JavaScript, Canvas. Ни библиотек, ни сборщиков,
ни установки.**

## Как запустить

Открыть `tanki.html` двойным кликом в любом браузере. Всё. Локальный
сервер не нужен — это принцип проекта, а не временное упрощение.

Перед боем: выбрать режим (Death Match / Capture the Flag) и число для
победы, затем «В бой». Управление — клавиатура (`↑↓←→` или `WASD`, `Z`/`X`
башня, `Пробел` — держать для выстрела). Подробности — в `.modules/idea.md`.

## Запуск в Docker (для разработки/тестирования)

Двойной клик остаётся главным способом. Docker — дополнительный: даёт
одинаковый воспроизводимый запуск через `http://` и фундамент под сетевую
ступень. Контент статический, поэтому образ не собираем — стоковый nginx
монтирует папку проекта, правки видны по F5 без пересборки.

```sh
docker compose up -d                     # поднять контейнер
open http://localhost:8080/tanki.html   # открыть игру
docker compose logs -f                   # смотреть логи (Ctrl+C — выйти)
docker compose down                      # остановить и убрать контейнер
```

Порт `8080` на хосте → `80` в контейнере (см. `docker-compose.yml`). Папка
монтируется только на чтение (`:ro`).

## Структура репозитория

| Путь | Что это |
|---|---|
| `tanki.html` | Игра целиком: стили, `CONFIG`, `Tank`, рельса, бот, режимы, рендер, цикл. Единственный исполняемый файл. |
| `.modules/idea.md` | Дизайн-документ: механики, баланс, устройство кода, извлечённые уроки. |
| `garage/` | Склад **спецификаций** корпусов и пушек (Markdown, не код). Основа для будущего гаража, где можно будет менять вооружение. |
| `CHANGELOG.md` | История версий (дублирует шапку HTML-файла). |

`garage/` сейчас хранит описания, а не рантайм-модули: игра остаётся одним
файлом, `CONFIG` внутри него — источник истины по игровым числам, а карточки
гаража описывают сущности и их происхождение из оригинала.

## Версии

Рабочий файл всегда `tanki.html` — имя стабильное, не переименовывается.
Версию несут:

- константа `VERSION` в шапке `tanki.html` (показана под ареной);
- git-теги (`v0.10`, `v0.11`, …) на коммитах-релизах;
- `CHANGELOG.md` — свежее сверху, незарелизенное копится в разделе
  `Unreleased`.

**Релиз** (когда `Unreleased` дозрел):

1. поднять `VERSION` до нового номера, перенести `Unreleased` → `## X.Y` с датой;
2. `cp tanki.html tanki_vX.Y.html` — снимок под скачивание («скачал файл —
   видно сборку»);
3. `git tag vX.Y`.

Так рабочая правка не тянет за собой переименование файла и правку ссылок в
README/Docker, а распространяемый снимок с версией в имени всё равно есть.

## Порядок роста проекта

1. Одиночная игра против бота ← **мы здесь (v0.9)**
2. Локальный мультиплеер в браузере
3. Сетевая игра

Разбиение игры на отдельные JS-модули (и, значит, локальный сервер) оправдано
не раньше ступени мультиплеера. Пока — single-file.

## Ветки

- `main` — стабильные релизы.
- `stage-prod` — предрелизная сборка перед пушем в прод.
- `feature/*` — рабочие ветки под конкретное изменение.

Поток: `feature/*` → `stage-prod` → `main`. Мердж и pull request автор делает
сам.
